# Spendova - Folder & File Structure

This document explains the purpose of every major folder and critical file in the Spendova (ExpenseMate) repository. Use this as your map whenever you need to find where a specific feature is built.

---

## 📂 `/public`
Contains static assets that are served directly to the browser.
- **`firebase-messaging-sw.js`**: The Service Worker file. This runs in the background of the user's browser and listens for incoming Push Notifications from Firebase even when the app is closed.
- **`manifest.json` / `site.webmanifest`**: Configuration files that allow browsers (like Chrome or Safari) to install Spendova to the user's home screen as a Progressive Web App (PWA).

---

## 📂 `/src`
The heart of the frontend. This contains the entire React (Vite) application.

### 📁 `/src/components`
Reusable UI pieces that don't belong to just one single page.
- **`/ui`**: Contains raw, standardized building blocks (Buttons, Dialogs, Inputs, Toasts) generated by shadcn/ui.
- **`/drawers`**: Contains global slide-up menus (like the Universal Add Drawer).
- **`AppLoader.tsx`**: The beautiful full-screen loading spinner you see when the app is starting up.

### 📁 `/src/hooks`
Custom React hooks that manage state and frontend business logic.
- **`useAuth.tsx`**: **Highly critical.** This manages the user's login session. It automatically checks if the user is logged in, logs them out if their session expires, and provides the `user` object to the rest of the app.
- **`use-toast.ts`**: The hook you call when you want to show a small success/error popup at the bottom of the screen.

### 📁 `/src/integrations/supabase`
- **`client.ts`**: This creates the `supabase` object used everywhere in the app to talk to your database.
- **`types.ts`**: TypeScript definitions that perfectly match your database tables.

### 📁 `/src/lib`
Utility files, scripts, and SDK initializations.
- **`notifications.ts`**: The central brain for Push Notifications on the frontend. It automatically detects if the user is on the Web or a Native Android APK, asks for the correct permissions, and saves their device token to the database.
- **`device-session.ts`**: Tracks active logins so users can see (and remotely log out) other devices they are logged into.
- **`friendly-error.ts`**: Translates ugly database errors into friendly, human-readable text.

### 📁 `/src/pages`
The actual screens/routes that the user navigates to.
- **`Auth.tsx`**: The Login, Registration, and Forgot Password screen.
- **`VerifyOtp.tsx`**: The unified 6-digit code screen. It perfectly handles both "Verify Email" (when signing up) and "Reset Password".
- **`Index.tsx`**: **The biggest file.** This is the main "Splitwise" dashboard. It contains all the complex frontend logic for adding friends, creating groups, splitting expenses, and settling balances.
- **`Profile.tsx`**: The user settings page (Avatar uploads, changing names).
- **`Admin.tsx`**: The secret dashboard for administrators to view system stats or put the site into Maintenance Mode.
- **`InviteAccept.tsx`**: The screen a user lands on when they click an email link to join a Group.

### 📁 `/src/pages/Ledger`
Because the "Ledgers" (Budgeting) feature is so massive, it has its own dedicated folder.
- **`index.tsx`**: The screen listing all Ledgers a user belongs to.
- **`LedgerDetail.tsx`**: The deep-dive screen showing the charts, expenses, and members for a specific ledger.
- **`/components`**: Small UI pieces specifically for Ledgers (like the Budget summary cards).
- **`/drawers`**: The slide-up menus for creating a new ledger or adding an expense to a ledger.
- **`InviteLedgerAccept.tsx`**: The screen a user lands on when they click an email link to join a Ledger.

## 📂 `/supabase`
The backend configuration, living entirely outside of the React app.

### 📁 `/supabase/migrations`
Contains `.sql` files. These files dictate exactly how your PostgreSQL database is structured.
- It contains `CREATE TABLE` commands.
- It contains **Row Level Security (RLS)** policies (which ensure users can't read other people's data).
- It contains `pg_cron` jobs (like the database telling the server to delete old data every midnight).

### 📁 `/supabase/functions`
Contains **Edge Functions**. This is your serverless backend code (written in Deno/TypeScript).
- **`/send-push-notification`**: Triggered automatically by a Database Webhook whenever a row is inserted into the `notifications` table. It sends FCM payloads to user devices.
- **`/send-ledger-notification`**: Handled via frontend triggers to notify Budget Admins of new expenses, or users of paid expenses.
- **`/cron-ledger-reminders`**: Triggered daily at 10 PM IST via `pg_cron` to remind Budget Admins of unpaid ledger expenses.
- **`/send-invite` & `/send-ledger-invite`**: Triggered by the frontend to send beautifully formatted HTML emails using Nodemailer.
- **`/send-auth-otp` & `/reset-password-with-otp`**: Securely handles sending passwords and verification codes to users.
- **`/generate-monthly-reports`**: Triggered automatically by a cron job on the 1st of every month to email PDF summaries to users.
- **`/send-shared-notification` & `/send-expense-notification`**: These handle inserting rows into the `notifications` table. *(Note: Their email-sending logic is currently commented out to prevent spam, favoring push notifications instead).*
